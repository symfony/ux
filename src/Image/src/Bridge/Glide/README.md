# Symfony UX Image: Glide

**EXPERIMENTAL** This component is currently experimental and is
likely to change, or even change drastically.

[Glide](https://glide.thephpleague.com/) integration for Symfony UX Image. Glide is an image server written in PHP that runs in your own infrastructure, so no third-party service is needed. This bridge generates the Glide URLs; your application, or another one, serves them with Glide.

## Installation

Install the bridge using Composer and Symfony Flex:

```shell
composer require symfony/ux-glide-image
```

## DSN example

```dotenv
UX_IMAGE_DSN=glide://default/img
```

The host is the domain that serves Glide. `default` generates URLs relative to your application, like `/img/uploads/hero.jpg?w=800`. Any other host, like `glide://images.example.com/img`, generates absolute `https://` URLs. The path, `/img` here, is the path Glide is served under. It is optional.

## Signed URLs

Sign every URL, so that Glide serves only the URLs your application generated. Give the sign key as the `sign_key` DSN option:

```dotenv
UX_IMAGE_DSN=glide://default/img?sign_key=the-sign-key
```

Every generated URL then carries the matching `s` parameter, as [Glide's own signature](https://glide.thephpleague.com/3.0/config/security/) checks it. The signature covers the path as it appears in the URL, which is what Symfony's `Request::getPathInfo()` returns.

> [!WARNING]
> The sign key signs every URL: anyone holding it can request any transformation of any image. Keep it out of the files you commit, and store it the way you store your other secrets.

## Serving the images

Install Glide and its [Symfony adapter](https://github.com/thephpleague/glide-symfony), then add a controller for the path of the DSN:

```shell
composer require league/glide:^3.0 league/glide-symfony
```

```php
// src/Controller/GlideController.php
namespace App\Controller;

use League\Glide\Filesystem\FileNotFoundException;
use League\Glide\Responses\SymfonyResponseFactory;
use League\Glide\ServerFactory;
use League\Glide\Signatures\SignatureException;
use League\Glide\Signatures\SignatureFactory;
use Symfony\Component\DependencyInjection\Attribute\Autowire;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;
use Symfony\Component\Routing\Attribute\Route;

final class GlideController
{
    #[Route('/img/{path}', name: 'glide', requirements: ['path' => '.+'], methods: ['GET'])]
    public function __invoke(
        Request $request,
        string $path,
        #[Autowire('%kernel.project_dir%')] string $projectDir,
        #[Autowire('%env(GLIDE_SIGN_KEY)%')] string $signKey,
    ): Response {
        try {
            SignatureFactory::create($signKey)->validateRequest($request->getPathInfo(), $request->query->all());
        } catch (SignatureException) {
            throw new NotFoundHttpException();
        }

        $server = ServerFactory::create([
            'source' => $projectDir.'/public',
            'cache' => $projectDir.'/var/glide',
            'max_image_size' => 4000 * 4000,
            'response' => new SymfonyResponseFactory($request),
        ]);

        try {
            return $server->getImageResponse($path, $request->query->all());
        } catch (FileNotFoundException) {
            throw new NotFoundHttpException();
        }
    }
}
```

The `source` is the `public/` folder, so `src` stays the path your application serves the image from.

The Symfony adapter does not support Glide 4 yet. With Glide 4, read the image generated by `$server->makeImage()` from `$server->getCache()` and return it in a `StreamedResponse` instead. The generated URLs work with Glide 3 and 4.

## Parameter mapping

`ImageTransformation` properties are mapped to Glide's [query parameters](https://glide.thephpleague.com/3.0/api/quick-reference/):

| `ImageTransformation` | Glide parameter | Notes                         |
| --------------------- | --------------- | ----------------------------- |
| `width`               | `w`             |                               |
| `height`              | `h`             |                               |
| `fit: Fit::Cover`     | `fit=crop`      |                               |
| `fit: Fit::Contain`   | `fit=contain`   |                               |
| `format`              | `fm`            | `jpeg` becomes `jpg`          |
| `quality`             | `q`             |                               |
| `operations`          | _(as given)_    | merged in verbatim, see below |

## Supported operations

Any of the following keys can be passed through `ImageTransformation::$operations` and are forwarded as-is as query parameters:

`or`, `flip`, `crop`, `bri`, `con`, `gam`, `sharp`, `blur`, `pixel`, `filt`, `bg`, `border`, `dpr`, `mark`, `markw`, `markh`, `markx`, `marky`, `markpad`, `markfit`, `markpos`, `markalpha`.

See the [full parameter reference](https://glide.thephpleague.com/3.0/api/quick-reference/) for what each one does.

## Supported formats

`avif`, `webp`, `jpeg`, `png`, `gif`.

Glide has no automatic format negotiation. `ux_image()` renders its `<img>` in the last configured format Glide supports; use `ux_picture()` to render one `<source type>` per configured format. Glide encodes AVIF only when the image library of PHP, GD or Imagick, supports it. Otherwise, remove `avif` from the `formats` option.
